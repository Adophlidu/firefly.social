PR Review Checklist for AI Assistant
================

Review all changes in the PR by diffing the current branch with the main branch. Focus on the following common issues in this codebase.

Performance & Logic
--------------------------------
  - Identify and prevent potential performance or logic errors.
  - Check for duplicate implementations or code snippets.

Coding Standards
--------------------------------
  - Ensure addresses are fully lowercased when used as query keys in `useQuery`.
  - Replace `console` with `Logger` if available in the codebase.
  - For Next.js projects, implement `generateMetadata` when adding a new page.
  - Ensure exhaustive enum handling; always include `unreachable` or `safeUnreachable` in switch-case defaults.
  - Import types only from @farcaster/core.

General Quality
--------------------------------
  - Identify and fix typos.

Creating a Modification PR
--------------------------------
  - When an issue is found, apply the necessary fixes in the code.
  - Validate changes:
    - Run `npm run typecheck` to ensure no type errors.
    - Run `npm run test` to ensure all unit tests pass.
  - Ask for confirmation before proceeding with the full update workflow:
    - Stage and commit all changes on a new branch against the reviewed branch.
    - Use a simple, concise commit title and provide detailed information in the body.
      - Follow the [Conventional Commits](https://www.conventionalcommits.org/) specification.
    - Push the branch to the remote repository and create a PR against the reviewed PR.
      - Format the PR description according to `PULL_REQUEST_TEMPLATE.md`.
      - Open the PR link automatically if creation succeeds.
